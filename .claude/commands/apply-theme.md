# /apply-theme 命令

当用户要求修改主题、统一样式、引入 UI 库或重构样式代码时，必须遵循以下原则。

---

## 核心原则：增强而非替换

主题/模板/库是**增强工具**，不是替代品。必须在保留原有功能的基础上引入。

---

## 执行步骤

### 1. 先理解后执行

- 用 `git show HEAD:文件路径` 查看原始代码的完整实现
- 理解原有代码的功能、命名、结构
- 区分核心功能与可替换部分
- 如果有参考模块，逐项对比其实现

### 2. 最小化修改

- 每次只修改一个文件
- 仅添加必要的引入语句
- 保留原有的变量、类名、样式定义
- 新增内容作为可选增强，不强制替换原有实现

### 3. 逐步验证

修改后立即检查：
- [ ] 原有功能是否保留？
- [ ] 页面布局是否正常？
- [ ] 视觉效果是否正确？
- [ ] 交互功能是否正常？

如果出错，立即回滚而非继续修改。

### 4. 多模块一致性检查

如果涉及多个模块：
- 新模块必须逐项对比参考模块的实现
- 检查所有视觉效果、动画、布局结构
- 检查全局样式是否与框架类产生优先级冲突

---

## 禁止行为

- 删除原有的变量定义和样式实现
- 用新类名批量替换原有类名
- 凭记忆恢复代码（必须用 git 对比）
- 批量修改多个文件后才验证

---

## 回滚方案

如果修改导致功能损坏：

```bash
# 查看原始文件
git show HEAD:路径/文件名

# 恢复单个文件
git checkout HEAD -- 路径/文件名
```

---

## 适用场景

- 引入新的 UI 框架或主题
- 统一多个模块的样式
- 重构样式代码
- 迁移到新的组件库
- 新模块对齐已有模块风格
